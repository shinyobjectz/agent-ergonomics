When what they need lives somewhere else, readers guess

People guess slowly. Agents guess confidently, and break things without noticing.

  • A copy of the logic in another fileChange one and the other breaks. Keep pieces that change together in one place.
  • A flag only the docs mentionThe agent calls what the docs say, and the parser refuses it. Generate the docs from the parser.
  • A term explained three screens after it's usedIntroduce each idea where it's first needed, with an example.
  • A sentence that only makes sense to whoever was in the chatWrite for the person reading it, not for the conversation that produced it.

Three skills

Each one starts when a task fits, or when you ask for it by name.

agent-ergonomics hands its text to purpose-built and its concepts to first-read, so running the first often runs all three.

agent-ergonomics

Untangles code so a typical change lands in one place, and redesigns what agents act through (CLIs, MCP tools, APIs, errors) so they can tell what to do and whether it worked.

One fix from a decision log Declare each command once, and generate the parser, the help and the docs from it.
  • cli/args.ts:12 parses --dry-run by hand, and docs/cli.md documents it separately.
  • --force is in the docs but not in the parser.
  • 4 of 10 agent runs parsed the human table instead of the JSON.

Each fix is written above the problems it solves, so one change clears several.

Reach for it when a change keeps touching five files, or agents loop on a tool. It takes numbers before and after, so you know whether it helped.

purpose-built

Writes copy, docs, flows and plans for the reader at the moment they read it, with nothing that sounds generated and nothing left over from the chat.

Reach for it when text sounds generated, a flow has dead ends, or docs mention “the new version” to readers who never saw the old one.

first-read

Makes an app or a tool understood on first contact. It lists every concept a new reader meets, and cuts them to the few the first task needs.
