What it fixes

Ask your agent about any of these.

  • A small change means editing five filesFinds the code that should live together and writes a step-by-step plan to restructure it.
  • Agents keep misusing your CLI, API or MCP toolsFixes the names, flags, output and error messages agents rely on, and measures the result before and after.
  • Your copy sounds like AI wrote itRewrites it short, specific and plain: no hype, no filler, nothing left over from a chat.
  • New users don't understand your appCuts the concepts and jargon a newcomer meets before they get anything done.

People and agents get stuck in the same places

People skim and guess. Agents read every word and act on it. Both fail when what they need isn't where they are: a flag only the docs mention, two names for one thing, an error that doesn't say what to do next.

So fixing it for one fixes it for the other.

Agents also fail loudly. Their transcripts show exactly where a surface lets readers down, which makes them a good way to measure UX too.

How it works

It looks at evidence before opinions, writes a plan, and checks each change against both readers. It works on code and interfaces, words, and concepts.

Code and interfaces

It reads your git history, dependency graph and agent transcripts, then restructures the code so each change happens in one place and fixes the CLIs, APIs and MCP tools agents use. It measures before and after, so you can see whether it helped.
